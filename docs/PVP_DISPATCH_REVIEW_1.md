## Spec and implementation assessment

**Hook admission and OFF preservation.** `DispatchHook.java:24–38` hashes the entire ASM-normalized class, excluding debug tables and frame encoding. Actual published and shaded normalized hashes are respectively `1cb1a2db1294b640d628e2e8a0726ea5db82b242d31b21ca4e70476d69151642` and `6d127d1ce0a5b347189230c20e7453defdd91b43145174d0a511791872ba7b7c`. Exact original map/method access and descriptors are checked as well. Unknown method/map/name/initializer bodies, altered subscription/removal code, and a duplicate Hook application reject without changing the node. No version-only or broad-shape fallback is present.

The injected prefix leaves every original `postEvent` instruction node in the same suffix order and retains the original exception-handler objects/order after the added handler. OFF/rejected execution reaches that body, including Kotlin's original null-input check/message. Independent review also compared every non-post method's serialized instructions/metadata before and after the Hook, including `<clinit>`, and checked original field ordering. Original `INSTANCE`/map initialization is retained; the synthetic final marker has its constant value, and the volatile seam-failure field defaults to null. OFF preserves original behavior while still paying admission/diagnostic prefix costs; it is not an uninstrumented timing baseline.

**First definition, helper visibility and original state.** Hook construction passes a string target to the actual Hook superclass. Mod construction/preInit have no executable EventBus reference. A private actual-shaded-ABI check constructed the artifact Hook and mod and invoked preInit without defining EventBus. There is no retransformation, instrumentation use, loader/API replacement, or early agent. Injected `GETSTATIC EventBus.map` passes the actual caller definition's original map; no shadow registration bus/map is introduced. Runtime admission checks helper identity through the bus loader, bus identity through the control-helper loader, and the caller's strict marker before callbacks (`DispatchRuntime.java:43–61`). A helper from a different loader is rejected. Missing helper linkage leaves the original method usable and records failure on the transformed bus itself; helper counters cannot count calls that cannot reach that helper.

**Preflight, snapshots and supported races.** Requested admission requires an exact ConcurrentHashMap and exact COW values at every existing traversed hierarchy level before the first callback. Unknown superclass lists and COW subclasses reject the entire candidate post before any candidate callback. Preflight does not create missing lists or acquire dispatch snapshots. Dispatch retains `computeIfAbsent` at each actual traversal level and takes that level's COW snapshot after earlier-level callbacks. Public subscribe/unsubscribe operations preserve exact COW types, so their races with preflight do not require map/list replacement assumptions. Review specifically admitted a post, then removed/added listeners through the original public API before dispatch, and verified fresh child/parent snapshots. Same-level changes after iterator creation remain excluded from that snapshot; later-level changes are visible. Duplicate consumers, identity-based unsubscribe, synchronous nesting, caller thread and event identity remain intact. No `Object`/interface delivery or cancellation filter is added.

**Exceptions and no replay.** The injected LinkageError handler covers admission only and ends before `dispatch` (`DispatchHook.java:62–83`). Actual callback LinkageError reaches the caller, rather than the original body. Dispatch catches Throwable only to count/report and rethrows the same object through its generic checked rethrow; it never returns a fallback decision. Direct, reflected and nested exceptions stop later/superclass delivery. Review additionally injected preallocated checked Exception, InvocationTargetException and AssertionError objects through registered Consumers and asserted exact returned identity, a single callback, zero baseline replay and one failure. An unexpected list after preflight stops without replay; arbitrary reflective state corruption is outside supported public-API race parity.

**Controls and diagnostic meaning.** Requested state initializes false and is neither saved nor activated by environment/property/config. ON alone does not establish active evidence. Available reflects runtime admission; active requires requested/available plus an actual candidate entry since OFF→ON/reset. Hook application in a transformer helper and marker observation in the executing helper are reported separately. Nested OFF preserves the already-admitted outer candidate while nested/later admissions use baseline; ON inside a baseline callback enables the nested admission and creates active evidence only when it enters dispatch. Reset retains request and Hook evidence and clears active evidence without interrupting the outer post.

Counters are intentionally nontransactional diagnostic snapshots, as the implementation report states. A blocked post spanning a concurrent reset produced `effectivePosts=0, completedPosts=1, active=false`; reset inside a callback followed by a nested candidate produced `effectivePosts=1, completedPosts=2, active=true`. Both traces preserved all callbacks. Failures/completions from posts entering before reset can land afterward, and nested failures can count both entered posts. These are not paired measurement epochs or callback counts. Their documented meaning is sufficient for this experiment; performance qualification must avoid treating reset-spanning counters as a coherent sample.
