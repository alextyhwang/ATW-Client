# Weave 1.4.1 / Lunar 1.8.9 rendering constraints

Researched 2026-10-05 on `performance/weave-1.4.1-mc1.8.9`. Research only: repository/source reads, artifact hashes, ZIP metadata and read-only `javap`; no implementation, build, installation, game launch, attachment or benchmark. Read [AGENTS.md](../../AGENTS.md), [MODS.md](../../MODS.md), and Overlay's [agent notes](../../weave-mods/optimal-zone/AGENTS.md) / [README](../../weave-mods/optimal-zone/README.md). **Fact** means upstream implementation, inspected artifact, or explicitly attributed repository record; **inference/proposal** is labeled separately.

## Decision and baseline

**Inference:** build on narrow, guarded CPU-work reductions around the existing renderer. Weave permits deep transformations, but supplies neither a replacement-renderer compatibility contract nor proof that a vanilla method body is the one Lunar executes.

**Repository record:** the guarded name parse cache observed 473.064 → 532.491 FPS (+12.562%) in two short moving OFF→ON→ON→OFF Bedwars Practice blocks at windowed 2560×1421. Terrain, glyph and error-poll optimizations stayed OFF. This is limited local evidence, not a Hypixel result, GPU-time measurement, guaranteed gain or doubled-FPS result. Hypixel connectivity remains unresolved. Preserve this baseline and its original GL checks. [Measurement report](../NAME_PARSE_PERFORMANCE.md)

## Actual pinned architecture

**Verified artifacts:** `runtime/weave/Weave-Loader-Agent-1.4.1.jar` hashes to `9fbcada12fc031426eb80613b02b9be31d83add6a116720b7e17e4439d28b4c8`; `runtime/weave/maven-repository/net/weavemc/api/api-v1_8/1.4.1/api-v1_8-1.4.1.jar` hashes to `a536d86e37d61a7ac730e598368cf1c128662c44fc5ae18936f1e529eacea8c9`. Both match [the fetch script](../../scripts/fetch_weave_runtime.ps1). The loader manifest declares `AgentKt` as premain, version 1.4.1 and retransformation capability; embedded loader properties agree. The upstream [1.4.1 release][release] resolves to commit `f5509fe9eb9c2004996ee65ed3de3ced20ca44bf`; source links below pin that commit, not current HEAD.

**Facts:**

- The agent discovers/remaps mods, registers bootstrap transformers, and sets Lunar's `ichor.prebakeClasses=false`. Bootstrap intercepts `net/minecraft/client/main/Main`, adds Weave to its game classloader, and instantiates the loader there. URLClassLoader subclasses receive accessors/delegation changes. This is agent injection into Lunar's existing classloading path. [Agent][agent], [Bootstrap][bootstrap], [classloader transformer][classloader]
- The loader registers `InjectionHandler`, resolves the versioned Minecraft API, registers mod hooks, populates sandboxed Mixin modifiers/access wideners, then calls `preInit(Instrumentation)`. A separate hook invokes `init()` at the head of `Main.main`: this does **not** mean a world or GL context already exists. Entrypoints are instantiated separately for each phase; avoid relying on instance fields carrying preInit state into init. Keep constructors/preInit game-free. [Loader][loader], [init hook][init], [initializer API][initializer], [instantiation helper][utility]
- `Hook(String... targets)` takes internal class names in the **mod's namespace**; `transform(ClassNode, AssemblerConfig)` edits bytecode. Injection groups matching modifiers by namespace, remaps the node between them, applies modifiers, and writes runtime-named bytes. It defaults to `COMPUTE_MAXS`; `cfg.computeFrames()` requests frame computation. Hooks are not constrained to the built-in events. [Hook API][hook], [InjectionHandler][injection]
- Lunar below 1.16.5 defaults to runtime `mcp-named`; classpath defaults to `official`. Runtime and classpath names are distinct concepts. Weave's mapping/hierarchy providers include vanilla bytes, so they do not establish the semantics of Lunar-added members. [Mappings][mappings]
- Loader source shades ASM/Mixin and other dependencies; remapping rewrites mod references into those shaded packages. Local `javap` confirms the packaged Hook accepts `net.weavemc.loader.impl.shaded.asm.tree.ClassNode`. Fingerprints must use stable operand kinds/values, not ASM implementation class names. The manifest's ASM “9.7” value is hard-coded by the shading script; the tag's dependency catalog pins ASM 9.9.1, so that manifest value alone does not identify the dependency version. [Shading][shade], [catalog][catalog], [Mappings][mappings], [repository fingerprint code](../../weave-mods/atw-render-boost/src/main/java/com/atw/renderboost/hook/TerrainEvidence.java)

**Build/package facts:** [Render Boost's Gradle file](../../weave-mods/atw-render-boost/build.gradle.kts) pins plugin/API/API-v1_8 1.4.1, Minecraft 1.8.9, MCP named mappings, Java 17 toolchain and Java 8 class files. It explicitly sets `compiledFor=1.8.9` and currently registers seven hooks; the README's older “five hooks” sentence is stale. Upstream Gradle generates `weave.mod.json` and compiles against remapped **vanilla** Minecraft plus compile-only libraries, not a complete Lunar SDK. [Gradle plugin][gradle], [dependency preparation][dependencies]

[src/launch/offlinelauncher.cpp](../../src/launch/offlinelauncher.cpp) supplies the pinned agent, private home/mods/Maven paths and `weave.vanilla.jar.path`; it removes inherited `-Dweave.*` arguments before adding canonical settings. `weaveOffline` defaults true. This controls API resolution, not multiplayer connectivity. Preserve executable-local `config/settings.json`, `data/home/.weave/mods`, private Lunar/Minecraft paths and the portable contract. [PORTABLE.md](../PORTABLE.md), [Config](../../src/config/config.cpp), [API resolution implementation][loader]

## Feasible hooks and their limits

| Surface | Verified behavior | Constraint / planning implication |
| --- | --- | --- |
| HUD events | API hooks `GuiIngame.renderGameOverlay`: Pre at entry, Post before the **last** RETURN. [Source][hud] | Useful for Overlay/HUD work; Post is not a finally block and misses exceptional/other exits. Restore state locally. |
| World event | Implementation inserts into `EntityRenderer.renderWorldPass` immediately before the `"hand"` profiler constant, reading partial ticks from slot 2. Packaged API bytecode confirms this despite a misleading “head” source comment. [Source][world] | Treat it as that specific pass location, not a frame-begin hook or guaranteed once-per-frame callback. |
| Living renderer | `RendererLivingEntity.doRender`: cancellable Pre at entry; Post before the last RETURN. [Source][living] | Cancelling Pre returns before Post. Existing chams rely on normal render/state sequencing; entity culling needs explicit treatment of hidden-player overlays and all render layers. |
| Frame/HUD scopes | Render Boost directly wraps `Minecraft.runGameLoop()V` / `GuiIngame.renderGameOverlay(F)V`, including exception cleanup. [FrameHook](../../weave-mods/atw-render-boost/src/main/java/com/atw/renderboost/hook/FrameHook.java), [HookSupport](../../weave-mods/atw-render-boost/src/main/java/com/atw/renderboost/hook/HookSupport.java) | Feasible observation/invalidation seams. Their timing is CPU wall time and includes limiter/presentation effects; hook installation is not an optimization result. |
| Name conversion | Ten captured class gates protect one codec callsite; cache hits reconstruct fresh native objects. [README](../../weave-mods/atw-render-boost/README.md), [runtime guards](../../weave-mods/atw-render-boost/src/main/java/com/atw/renderboost/cache/NameParseRuntime.java) | Best demonstrated pattern: bounded immutable-data reuse while retaining original rendering/validation and fallback. Additional caches require their own semantics/provenance proof. |
| Glyph geometry | Current hook admits one exact isolated GL11 begin/end primitive. Lunar's captured path batches via WorldRenderer and records display lists. [FontHook](../../weave-mods/atw-render-boost/src/main/java/com/atw/renderboost/hook/FontHook.java) | Existing per-glyph cache is incompatible with that path. A font optimization would need a separately proved Lunar batching seam. |
| Terrain pointers | Existing hooks address VboRenderList/VertexBuffer and supporting state/lifecycle classes. [TerrainHook](../../weave-mods/atw-render-boost/src/main/java/com/atw/renderboost/hook/TerrainHook.java) | Narrow pointer-state reuse is technically implemented, but visual parity/live gain remain unproved. It retains draw/count/matrix work and rejects Regions/shaders/active Lunar bridge. Leave OFF. |

**Fact:** EventBus dispatch is synchronous on the posting thread and walks event superclasses; annotation listeners use reflection. **Inference:** avoid expensive per-event scans, allocation or redundant subscriptions on hot render paths; dispatch overhead is a profiling candidate, not a measured bottleneck here. [EventBus][eventbus]

## LWJGL, OpenGL and OptiFine coexistence

**Facts:** Mojang's [1.8.9 metadata][mojang] names LWJGL 2.9.4-nightly-20150209 for Windows. That establishes vanilla's dependency, not Lunar's exact bundled revision. Repository captures/source target the LWJGL 2 `Display`, `GLContext`, `ContextCapabilities` and private `ContextGL` API; do not substitute LWJGL 3's context/window API. LWJGL 2 upstream tracks capabilities/function pointers per current thread/context and rejects missing context. [LWJGL 2 source][lwjgl], [TerrainRuntime](../../weave-mods/atw-render-boost/src/main/java/com/atw/renderboost/terrain/TerrainRuntime.java)

**Repository record:** the packaged baseline uses OptiFine M6 pre2. Upstream lists that specific 1.8.9 preview, but its download listing does not document Lunar's transformed implementation. Local evidence includes `net.optifine.Config`, `VertexBuffer.vboRegion`, Lunar matrix-bridge methods and modified fonts. Do not apply an arbitrary decompiled vanilla/OptiFine body as runtime truth. [Validation record](../UPGRADE_VALIDATION.md), [OptiFine listing][optifine], [terrain fixture provenance](../../weave-mods/atw-render-boost/src/test/resources/terrain/README.md)

**Practical requirements:** capability-check the actual context/profile, not merely a reported GL version or GPU model. Current terrain admission requires compatibility arrays, effective VBOs, OpenGL 3.0/ARB VAO support, exact BLOCK layout/texture units, baseline VAO zero, expected array enables, no custom shader, no Regions, no display-list recording, and no active opaque Lunar matrix bridge. The runtime resolves context lifetime through guarded private reflection; this is a pinned implementation detail, not public LWJGL API. Failure must retain the original path. [TerrainEligibility](../../weave-mods/atw-render-boost/src/main/java/com/atw/renderboost/terrain/TerrainEligibility.java), [TerrainRuntime](../../weave-mods/atw-render-boost/src/main/java/com/atw/renderboost/terrain/TerrainRuntime.java)

The OpenGL specification makes VAOs context-local and says ARRAY_BUFFER binding is not VAO state. Consequently, a cache needs actual context lifetime, buffer upload/delete/region reassignment invalidation, correct client texture selector and original binding/pointer restoration. Integer object IDs or capabilities alone cannot prove lifetime. Keep GL work on the owning render thread, bound resource ownership, restore on exceptional exits, and latch failures. Preserve Minecraft's cached GL state as well as driver state. [ARB VAO specification][vao], [TerrainVaoCache](../../weave-mods/atw-render-boost/src/main/java/com/atw/renderboost/terrain/TerrainVaoCache.java)

**Repository constraint:** preserve one normal player render; visible fragments remain normal and the hidden overlay remains base-model-only. Re-rendering full players duplicates armor/items/layers. Broad culling or state shortcuts must preserve these features and HUD/LevelHead behavior; LevelHead remains the sole packet-to-chat bridge. [MODS.md](../../MODS.md), [Overlay notes](../../weave-mods/optimal-zone/AGENTS.md)

## What transformed evidence proves

**Facts:** InjectionHandler temporarily prefixes existing `MixinMerged` methods with `$weave_potentialConflict$`, applies modifiers, then restores names when serializing. Packaged-loader bytecode confirms the prefix. A post-load capture therefore need not match the ClassNode entering an ATW hook. Weave's optional dump contains its transformer output, not necessarily the final result after all later transformers. Serialized hook-input ClassNodes are not original class-file bytes. JVM retransformation may also alter constant-pool layout and method order; it reuses prior output from retransformation-incapable transformers without calling them again. [InjectionHandler][injection], [fixture provenance](../../weave-mods/atw-render-boost/src/test/resources/terrain/README.md), [Java Instrumentation][instrumentation]

Repository gates support only explicitly observed layouts. Detached comparison handles proved conflict names/session-derived symbols and narrowly observed initializer access differences; real declarations/references remain intact. The name gate separately admits recorded startup member orders. Missing fixtures, public-only tests, synthetic shapes or a loaded class name do not prove actual admission, execution frequency, final transformer composition, visual parity or speed. Private bytes remain ignored and unpublished. [TerrainHookStage](../../weave-mods/atw-render-boost/src/main/java/com/atw/renderboost/hook/TerrainHookStage.java), [NameParseHookStage](../../weave-mods/atw-render-boost/src/main/java/com/atw/renderboost/hook/NameParseHookStage.java), [Gradle capture modes](../../weave-mods/atw-render-boost/build.gradle.kts)

**Important limit:** manifest retransformation support is not arbitrary hot-patching support. InjectionHandler is registered without retransformation capability; JVM redefine/retransform rules also constrain schema changes such as added fields/interfaces. Restart is the existing installation contract. Weave's `SafeTransformer` exits on transformation failure; its optional bytecode check checks class name/version only, not full verification or GL correctness. New hooks must reject unsupported input before mutation rather than depend on loader recovery. [Loader][loader], [SafeTransformer][safe], [Java Instrumentation][instrumentation], [MODS.md](../../MODS.md)

## Modern Fabric mods and remaining work

**Facts:** Fabric discovers `fabric.mod.json`, Fabric entrypoints/dependencies and mixin metadata. Weave discovers its own metadata and initializer API. Weave's ability to run on a Fabric/Ornithe client, or use a Fabric-distributed Mixin library, does not make Lunar a Fabric runtime. As a concrete modern example, Sodium's **mc1.21.1-0.6.13** Fabric metadata requires Minecraft 1.21/1.21.1, Fabric Loader ≥0.16.0 and Fabric API modules, and declares OptiFabric incompatible. Renaming a jar or its mappings does not supply missing renderer classes/APIs/lifecycle or resolve OptiFine renderer ownership. **Inference:** reuse algorithm ideas only through an explicitly designed 1.8.9 Weave port with Lunar coexistence proof. [Fabric structure][fabric], [Sodium versioned metadata][sodium], [Weave client/mapping definitions][gameinfo]

**Unknowns:** current Lunar revision and exact bundled LWJGL bytes; complete transformer order/composition across enabled external agents; unobserved render/font/bridge paths; actual incremental CPU/GPU bottleneck after name caching; terrain guard/query overhead versus saved pointer work; Hypixel connectivity and Hypixel-specific visual behavior. Historical reports/captured profiles are not a fresh live audit. [Validation limits](../UPGRADE_VALIDATION.md), [measurement limits](../NAME_PARSE_PERFORMANCE.md)

**Proposed guard requirements for subsequent authorized work:**

1. Freeze loader/API/Lunar/mod/settings provenance; select one exact hot callsite and prove startup hook input, executable operands/handlers, descriptor, Mixin origin, actual loaded classloader and runtime use. Reject unknown/redefined inputs; never auto-expand allowlists.
2. Keep new experiments independently OFF. Preserve the measured name cache and original fallbacks, Minecraft version, quality, draw resolution, player layers and existing overlays. Use bounded immutable caches with world/resource/thread/evidence invalidation and fresh mutable return objects.
3. For GL changes, prove context/thread/state ownership and buffer lifetime before allocation or bypass; restore selectors/bindings/arrays and cached Minecraft state on every exit. Unknown OptiFine mode/bridge or cleanup failure disables the candidate.
4. Later validation must distinguish requested, admitted and **actually hit** paths, then establish visual/exception/lifecycle parity before repeated comparable moving multiplayer frame-time measurements. Do not enable terrain/glyph/error-poll candidates merely because source tests pass. This research performs none of those runtime steps.
