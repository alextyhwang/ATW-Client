## Current parse seam and preservation guarantees

**Code facts:** [NameParseHook.java][names-hook] branches at one exact `deserializeShowEntity` `Codec.decode(Object)` callsite after the existing plain serializer has produced the complete SNBT string. OFF/misses retain the original decode/cast/store. Hits reconstruct fresh native compounds and string tags; original key/type validation, UUID parsing, text/ShowEntity construction and handlers still execute. Getters, component/style conversion, serialization and the opposite `serializeShowEntity` path are not eliminated.

[NameParseCache.java][names-cache] stores only immutable original-decoded strings, keyed by exact full-string equality. Admission permits unique unquoted `name`, `id`, optional `type` fields with double-quoted values; nested/list/numeric/unquoted values, unknown/duplicate keys, backslashes, control characters and trailing input bypass. Limits: 256 LRU entries, 4,096-character keys, 524,288 retained UTF-16 key/field characters. This is a character bound, not a complete heap-byte bound. OFF/clear, reload, world/thread/evidence changes invalidate; helper failure latches fallback. Epoch checks bracket hit eligibility and reconstruction.

**Important distinction:** entries are recorded after a successful original parse/cast/store, **before** downstream key/UUID/result validation. Repeated invalid keys/UUIDs can therefore hit the tuple cache, but still throw from the original validation each time. [NameParseHookTest.java][names-hook-test] explicitly checks exception class/message and repeated key validation. The earlier [feasibility report][codec-report] proposed committing only after complete converter success; that proposal does not describe the final implementation. No exceptions or ShowEntity results are cached.

The ten-class gate checks 123 captured executable bodies, layout/constants and provenance; only detached comparisons normalize proved Weave conflict names. Separate exact startup layouts cover three observed PUBLIC-only `<clinit>` differences. Unknown code/order/access/provenance rejects; proof-marker/repeated-hook inputs fail closed rather than rebase dynamically. These guarantees are specific to admitted definitions, not general compatibility with every future Lunar transformer. [Hook][names-hook], [stage proof][names-stage], [startup correction][startup-report]. The JVM's treatment of initializer access flags supports this narrow comparison normalization; it does not justify arbitrary access widening. [JVMS 4.6](https://docs.oracle.com/javase/specs/jvms/se17/html/jvms-4.html#jvms-4.6).

## Measurement and test limits

- **Benchmark facts:** duration 5–240 s, warmup 1–120 s, 240,000 interval ceiling; warmup-crossing interval excluded, overflow aborts. FPS is frames/total interval time; median/p95/p99 use nearest rank. CPU frame-start intervals include limiting/presentation, not GPU execution. [BenchmarkSession.java][bench], [FrameStatistics.java][stats].
- **Guards:** active world/player, focus, no GUI/pause, stable world/window/tracked graphics settings. Stationary rejects position/yaw/pitch changes; moving permits them without verifying the intermediate route. Loaded counts are collection sizes, not rendered players, visibility or NPC identity. Lunar/OptiFine/ATW options, weather/time and crowd composition need external control. Start/end viewport snapshots do not monitor every frame's viewport. [Scene guard][scene], [runtime][runtime].
- **Mode qualification:** names-ON sampling needs active loaded singleton proof; evidence/lifecycle/failure changes abort. `namesCacheActive` requires measured hits. Terrain-ON requires eligibility and rejects measured fallbacks. Filenames `-off` label the shared frame/glyph switch, so names-ON samples can have `-off` filenames. Frame-policy fallback is exported but lacks terrain's strict rejection contract when terrain is OFF: explicitly exclude fallback/mixed-policy trials. [Runtime][runtime], [name runtime][names-runtime], [terrain benchmark guard][terrain-bench].
- **Recorded name result:** two OFF→ON→ON→OFF blocks, 10 s measured/1 s warmup, changing crowds/worlds, one 5m39s maintenance gap, no randomized confidence interval; p99 did not uniformly improve. ON recorded 1,296,464 hits, seven misses, 105–108 entries and no measured failures/rejections/invalidations. This gives no capacity-pressure reason to raise the 256-entry ceiling. [Measurements](../NAME_PARSE_PERFORMANCE.md).
- **Profiling:** deep pre-cache JFR had only 79 client Java and 26 client native samples; families overlap and sample counts are not duration budgets. The later moving diagnostic reported 48.34% sampled inclusive outer-name/frame wall share, but armor-stand calls dominated (245,926 versus 32,149 player-shaped calls). Its Windows CPU deltas were quantized at 15.625 ms and sometimes zero. Neither ratio is parser-only savings or post-cache headroom. [Deep attribution][deep-report], [live probe][probe-report]. Oracle explicitly distinguishes nanosecond precision from accuracy. [ThreadMXBean](https://docs.oracle.com/en/java/javase/17/docs/api/java.management/java/lang/management/ThreadMXBean.html).
- **Existing tests:** grammar/equality/bounds, fresh ownership, original calls/exceptions, runtime singleton/loader/marker checks, epoch races, startup/redefinition rejection, relocation, nested probe cleanup/deadlines/CPU fallback, statistics/scene guards and terrain restoration/failure paths are present under [src/test/java](../../weave-mods/atw-render-boost/src/test/java/com/atw/renderboost). Recorded delivery totals are 177 private / 131 public; not rerun here. [Build configuration][build] explicitly separates private terrain (30 fixtures), probe (11 inputs), codec (12 inputs), startup (10 reports) and optional restart proofs. Public passes cannot establish those private proofs or live GL/visual/FPS parity.

## Concrete next experiments and acceptance gates

These are **proposals for later authorized work**, not actions performed by this audit.

1. **Strengthen the existing baseline first.** Repeat names OFF→ON→ON→OFF in longer matched windows (30–60 s measured, at least 10 s warmup), at confirmed 2560×1421 windowed; reverse starting order across at least three blocks. Include a player-rich moving gameplay scene separately from the armor-stand lobby. Keep error/glyph/terrain OFF, probe/export idle, jar/JVM/driver/quality/features fixed; keep profiles/captures outside timed windows. Retain aborts and per-block distributions. Gate: ten admitted hooks, ON active hits, zero failure/guard/invalidation deltas, unchanged controls and visuals; repeatable improvement beyond OFF drift without repeatable p95/p99 regression. Hypixel remains a separate acceptance requirement once reachable.
2. **Profile residual names with the delivery cache ON.** Reuse the bounded counter/timing probe in separate matched scenes and a short deep CPU/allocation profile, followed by uninstrumented benchmarks. Seek remaining `serializeShowEntity`, plain/NBT serialization, component/style conversion, width bridging, and fresh NBT reconstruction costs. Existing probe has no direct codec timing; add only independently admitted bounded counters if attribution needs them. Gate: adequate class/coverage and completed-frame samples, demonstrated collector overhead, distinguish player/armor-stand work, no summing inclusive metrics. Reject a new cache if safe repeated input or material remaining cost is absent.
3. **Conditional narrow name extension.** If residual evidence supports it, investigate exact-input reuse of immutable serialization output at `serializeShowEntity`, or a width-only projection at `FontRenderer.bridge$getStringWidth(Component)`. These seams are identified by [codec evidence][codec-report] and [deep attribution][deep-report], not implemented. Gate: original implementation and complete input/config semantics, warning/exception/getter/callback parity, inherited style/Unicode/bidi/translation/bold/italic width parity, bounded storage and immediate fallback; fresh public objects and no cross-entity/per-tick mutable component reuse. Do not widen current SNBT grammar absent measured unsupported-input pressure and parser-side-effect proof.
4. **Separate existing Render Regions trial.** Keep names at the baseline and terrain VAOs OFF; change only Regions through its normal reload lifecycle, preserving AA/AF/shaders and quality. Compare matched OFF→ON→OFF movement after rebuild warmup. Gate: actual arena/multi-draw activation, unchanged logical geometry/order, no repeatable tail or streaming regressions, parity for translucent blocks/chunk seams/depth and chams stencil edges. Current terrain counters omit arena draws, so use separate narrow observational evidence. [Prior exact trial plan][regions-report].
5. **Measure dormant instrumentation cost before rewriting it.** A candidate could bypass inactive diagnostic work while preserving cleanup/invalidation and retaining a comparable benchmark mode. Targets: probe wrapper branch/return checks, terrain OFF forwarding/draw counters, unconditional frame/HUD clocks and per-frame benchmark settings-string creation while sampling. Gate: same names-active baseline and measurement method, no admitted-evidence rebasing, cleanup/exception/reload parity, observable paired improvement. Current code establishes overhead exists; its magnitude is unknown. [Frame/HUD hooks][frame-hook], [runtime][runtime], [terrain hook][terrain-hook], [probe hook][probe-hook].

**Overlay boundary:** read [Overlay AGENTS.md](../../weave-mods/optimal-zone/AGENTS.md) and [README](../../weave-mods/optimal-zone/README.md). Preserve the single normal player render, polygon-offset skin/armor/items, base-model-only hidden stencil silhouettes, normal visible fragments, team colors, minimap, projectiles and hit feedback; LevelHead remains the sole packet/chat bridge. Multiple intentional base-model stencil passes are not duplicate full player renders. [OccludedPlayerRenderer.java](../../weave-mods/optimal-zone/src/main/java/com/atw/optimalzone/render/OccludedPlayerRenderer.java).

For a later Overlay-specific experiment, static circle tables in `drawCircle`, `drawCircleRing` and `drawClippedWorldRing`, or adjacent per-skin face/hat quad batching, are concrete small seams in [PlayerMinimapRenderer.java](../../weave-mods/optimal-zone/src/main/java/com/atw/optimalzone/render/PlayerMinimapRenderer.java). Gate them on `/atwoverlay perf` evidence and total-frame improvement with identical geometry/order/skin alpha/interpolation/state. They are lower priority than residual name attribution: the old profile did not identify HUD as dominant. The [minimap backlog](../../weave-mods/optimal-zone/MINIMAP_OPTIMIZATION_BACKLOG.md) predates current tick snapshots, query-free HUD guards and adaptive sampling; those already exist and must not be proposed as new work.
